## Blocking evidence

The unique CR-2026-010-authorized V2 Run B
`stage2-g1-v2-b-20260718T092459Z-85a6a71ab953` passed preflight and then stopped in its first
production task, `FOUNDATION:BTCUSDT`. The first monthly build observed process peak RSS
`1,704,640,512` bytes against the frozen `943,718,400` byte limit. The runtime wrote
`FAILED_UNPUBLISHED`; completed tasks, staging files and published files are all zero. Group 1,
release, verify and compare did not execute.

This is a production resource-contract mismatch. It is not evidence of Stage 1 drift, Run A
drift, research-semantic change or a failed event comparison. The failed Run B and its Authority
must remain append-only and must not be resumed, deleted, republished or assigned a new meaning.

## Approved decision

Muce approved the following bounded correction:

1. profile the original failure day, month boundaries and deterministically selected highest-row
   BTC/ETH Trades days without publishing;
2. record baseline RSS, current RSS, peak RSS and Arrow table bytes at each production phase;
3. aggregate Trades one authorized Parquet row group at a time and never retain the full Trades
   day together with its second primitives;
4. explicitly release price/Trades source tables after their dependent feature is sealed;
5. preserve the fixed 1 GiB Arrow inflight hard limit and replace the invalid absolute 900 MiB
   peak-RSS gate with separately auditable current-RSS and baseline-relative peak-RSS gates;
6. freeze exact resource limits only after the approved real-data profile passes with margin;
7. run red/green, determinism and all repository quality gates before freezing a replacement
   Authority;
8. invalidate the current failed Run B, create one new unique replacement Run B, build all 80,784
   V2 partitions and compare all 61,776 Group-1 partitions to Run A.

The correction must preserve Stage 1, Preregistration, config, event/candidate identity, research
parameters and the 61,776-partition comparison contract. It requires a new final code commit,
replacement Authority Bundle and unique Run B ID. It may not reuse the failed Run B.
