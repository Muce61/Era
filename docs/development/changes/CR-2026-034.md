## Problem

The repository records the latest Stage 2 truth in several Markdown files, but they do not all project
one identical operational state. `CURRENT_STAGE.md` and the latest S2-T15 validation say that T15 is
stopped, no formal result exists, OQ-S2-009/010/011 remain blocking, SRP-S2-001 is not executable and
Stage 3 is locked. Older Task/registry text and the T15 write-capable CLI still expose states or paths
that can be read as executable under the pre-CR-2026-031 governance chain.

This creates a fail-open risk: a clean repository and an old PASS audit can be sufficient for code to
attempt Authority, binning, preflight or Run work even though the current human governance says those
operations are forbidden.

## Approved decision

Implement a current-state authority and fail-closed S2-T15 operation gate:

1. Add `configs/governance/current_development_state.json` as the single machine-readable authority
   for current Stage, Task, blockers, sealed Tasks and allowed/blocked operation classes.
2. Bind the state with a deterministic SHA-256 over canonical JSON excluding only `state_hash`.
3. Permit only `READ_ONLY_AUDIT`, `VERIFY_EXISTING_EVIDENCE` and `READ_ONLY_UI` in the present state.
4. Reject supplement creation, Authority freeze, bin freeze, preflight, Run, resume and publication
   before filesystem or external-run side effects.
5. Enforce the gate both at the CLI and at the lowest currently reachable T15 write entry points.
6. Add a strict governance consistency checker covering the machine state, Markdown projections and
   required code guard locations.
7. Synchronize stale Stage Registry, dependency and Task status text without changing V1.3.4,
   Stage 1 or sealed T10-T14 evidence.
