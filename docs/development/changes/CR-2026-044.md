# CR-2026-044 — Default rehearsal with explicit background-runtime waiver

## Metadata

- status: APPROVED / IMPLEMENTATION AUTHORIZED
- requested_by: Muce
- approved_by: Muce
- approved_at: 2026-07-25
- approval_source: direct request to make the seven-day receipt a default rather than absolute gate
- scope: Stage 2 Plan v1.3 unattended non-research-hours background runtime only
- stage3_locked: true

## Problem

The lightweight Stage 2 policy treated a final-code seven-day rehearsal receipt as an absolute
precondition for every full-history runtime. That default is useful, but it also prevents the human
operator from explicitly accepting the extra operational risk of an unattended background run
after the clean commit and full quality gate have already passed.

## Decision

- The final-code seven-day rehearsal remains required by default.
- A generic approval, a CLI boolean alone or absence of a receipt never implies a waiver.
- The human operator may explicitly approve one unattended non-research-hours background runtime
  without a rehearsal receipt.
- The exception is stored in the append-only formal approval and binds the current clean commit,
  Policy Hash, contract Hashes, full-history scope, operator, time, source and reason.
- The waiver cannot bypass the clean commit, full quality gate, ChainAuthority-before-Run ordering,
  input and contract Hash validation, unique run lock, complete reconciliation, full Verify,
  publication integrity, T16 boundary, T17+ lock or Stage 3 lock.
- The Web UI must show whether the active approval used a rehearsal PASS or the explicit waiver.
- Historical approvals, rehearsals, Authorities, Runs and failures remain unchanged.

## Allowed

- `AGENTS.md`
- Stage 2 Plan v1.3 lightweight operations text
- `configs/governance/stage2_active_policy_v2.json`
- lightweight approval, Authority, CLI and read-only UI code
- focused regression tests

## Forbidden

- `docs/spec/**`
- mutation of Stage 1 or sealed Stage 2 evidence
- an unbound `--skip` switch
- waiver of Hash validation, reconciliation, Verify, unique locking or publication integrity
- S2P13-T17+, Stage 3 or real execution
