## Blocking evidence

Run `stage2-g1-v2-b-20260719T045142Z-0eeb27e0be21` completed both Foundation Tasks and eight
BTCUSDT Group-1 PRICE owner months, then was stopped by the user while processing 2020-09-11. Its
checkpoint is `INTERRUPTED_RECOVERABLE`, revision 6, with no failure, no publication and no active
process. The run remains immutable evidence and may not be resumed with changed code or adopted as
Group-1 input.

The approved profile identified duplicate previous/current processing-day work, repeated reads of
overlapping Foundation fragments, ineffective ThreadPool parallelism, small legacy-hash runs and
daily Parquet rereads. These are execution defects only; no research or output semantic change is
approved.

## Approved correction

1. Calculate every processing day once, persist a write-once candidate-attempt cache and finalize
   each owner day from its current and previous processing-day receipts.
2. Reuse already verified Contract Price, causal-bar and Trades-primitive fragments through bounded
   instrument-local sliding caches.
3. Use a spawn-safe three-process month executor. Workers write isolated staging and the parent
   validates and commits results in deterministic manifest order.
4. Preserve every formal row and compatibility Hash while batching canonical row encoding, using
   larger deterministic external-sort runs and streaming Arrow batches to monthly writers.
5. Treat SIGINT, KeyboardInterrupt and approved user stops as `INTERRUPTED_RECOVERABLE`, with
   append-only stop evidence and no automatic continuation.
6. Add a local read-only Web progress service backed by atomic `progress-v2.json` evidence.
7. Performance objectives are observability gates, not integrity failures. A miss records
   `PERFORMANCE_OBJECTIVE_NOT_MET`; explicit Muce review may accept the measured ceiling without
   weakening semantic or integrity gates.
8. After correctness, performance and repository gates pass, supersede the stopped run by receipt,
   freeze a new Authority twice, copy only fully verified Foundation artifacts into a new run and
   rebuild all Group-1 output from scratch.

## Acceptance

The fixed BTC/ETH July benchmark must be semantically exact. The original target was four times
faster, with
processing-day duplication nearly eliminated, Foundation fragment reads reduced by at least 60%,
legacy run count reduced by at least 80% and average compute utilization at least 2.5 cores. Only
an explicit human acceptance may waive a performance-only miss. S2-T10 passes only after all
80,784 V2 partitions publish and all 61,776 Group-1 partitions exactly match formal Run A.

## 2026-07-19 implementation result

The execution-only correction is semantically exact on the frozen BTCUSDT/ETHUSDT July window:
9,314,723 rows and all 806 daily receipts reproduce the old legacy, V2 semantic, identity and
payload roots. Processing-day executions fell from 124 to 64, Foundation physical reads fell by
64.52%, compatibility sorted runs fell from 4,795 to 652, and external daily temporary files fell
to zero. The read-only progress service, recoverable interrupt state and worker termination path
are implemented.

The measured wall time fell from 996.78 seconds to 457.05 seconds (2.18x), and measured average
compute utilization was 1.73 cores. These miss the approved 4x and 2.5-core promotion gates.
No final Authority was frozen and no replacement Run B was created at that checkpoint.

## 2026-07-19 continued optimization and human decision

Further profiling and deterministic trials reached 329.69 seconds, or 3.02x, while reproducing the
same 9,314,723 rows, 806 receipts and packed aggregate Hash. A three-way month-segmentation attempt
regressed to 484.56 seconds because repeated Foundation loading doubled CPU work; it was rejected
and removed. The complete trial history is preserved in
[CR-2026-014-performance-history](../validations/stage_2/CR-2026-014-performance-history.md).

Muce accepted 3.02x as the practical ceiling of the current external-disk architecture and
authorized progression. The unmet 4x and 2.5-core objectives remain explicit performance anomaly
evidence but no longer block the final quality gate, Authority freeze or the unique replacement Run
B. All correctness, exact Hash, integrity, ownership, leakage and append-only gates remain hard.
