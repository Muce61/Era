## Trigger

S2-T11 v1.2 §14 and §21 require formal output but also state that its full research CLI must be
frozen by S2-T19 and written into a newly approved Task version; the current version must not
invent that interface. The passed S2-T19 Manifest freezes only the Group-1 candidate CLI. Its
`allowed_outputs` ends at candidate construction and contains no H1/H2 path artifact.

The v1.2 fixture capability, deterministic receipt contract and automatic UI projection pass all
tests, but no lawful command can create formal BTC/ETH path output. The append-only S2-T11 receipt
therefore correctly reports `BLOCKED / FULL_RUN_CLI_NOT_FROZEN_S2_T11_V1_2` rather than PASS.

## Requested decision

Approve a new S2-T11 v1.3 execution contract with one immutable interface:

```text
uv run python scripts/run_stage2_path_extraction.py {preflight,run,resume,verify}
```

The approved amendment must freeze before execution:

- the fixed S2-T10 published snapshot and Stage 1 logical hashes as read-only inputs;
- separate BTCUSDT and ETHUSDT execution and outputs;
- H1 Contract Price and H2 Trades source/catalog hashes;
- UTC event-nanosecond left-closed/right-open window semantics;
- H2 identity `(instrument, canonical_trade_id)` and order
  `(ts_event_ns, venue_trade_id, canonical_trade_id)`;
- a new S2-T11 run namespace and append-only staging/published/catalog/manifest/report/receipt
  layout, separate from every S2-T10 Run;
- preflight, resume, verify, invalidation and no-overwrite behavior;
- exact output datasets limited to H1 paths, H2 paths, path quality/gaps/ambiguity, lineage,
  catalogs, manifests, receipts and quality reports.

## Requested minimal additional paths

  observability paths.

## Acceptance conditions

1. Preflight binds immutable source, code, config and output-policy hashes before a Run ID exists.
2. A new Run cannot write into or reference an S2-T10 output directory as its own output.
3. BTC and ETH outputs, counters and hashes remain separate.
4. Resume requires identical frozen hashes and validates every completed output.
5. Verify is read-only; malformed, missing, symlinked, conflicting or overwritten evidence fails.
6. PASS requires complete full output, separate BTC/ETH hashes, all registered checks and a final
   validation hash in the append-only receipt chain.
7. UI derives state from receipts and never hard-codes PASS.
8. Ruff, strict mypy, strict Traceability, directed tests and complete pytest pass.

## Explicit non-goals

This change does not authorize MFE, MAE, time-to-activation, first-passage, AMBIGUOUS bounds,
conditional baselines, placebo, clustering, bootstrap, S2-T12 through S2-T20, Stage 3, real API,
testnet or real funds. It does not modify Stage 1, Run A, the fixed S2-T10 Run, published outputs,
208 objects or 208 Seals.

## Decision required

Muce must explicitly approve or reject CR-2026-021 and S2-T11 v1.3. Until approval, the fixture
capability remains reviewable, formal output remains BLOCKED, S2-T11 remains NO-GO and no full
path-extraction Run may begin.
