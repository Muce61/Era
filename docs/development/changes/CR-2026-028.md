## Evidence-backed problem

The first formal T15 Run stopped during Episode preparation before matching or publication. T15
reconstructed Context at the final Episode `available_at_ts`, while T10 evaluated and sealed Context
at the bound price-trigger/Hold time. An Episode crossing an UTC hour boundary can therefore observe
an extra closed 1H bar and disagree with its sealed T10 Context.

Read-only reconciliation proved that every registered H2 Episode has exactly one conflict-free
`(trigger_id, event_parameter_set_id)` binding: BTC `220,201 / 220,201`, ETH
`312,507 / 312,507`; all bound trigger states are `UP / PASS`. Binding only by `trigger_id` is
forbidden because that identity is reused across parameter sets.

## Proposed correction

1. Episode Context is read directly from the sealed T10 `price_triggers` row keyed by
   `(trigger_id, event_parameter_set_id)`.
2. Control Context continues to be reconstructed at the control anchor with the frozen
   `CAUSAL_EMA20_1H@1.0` implementation.
3. Episode volatility, activity and key-level distance remain reconstructed causally; no outcome is
   read and no matching rule is relaxed.
4. `price_triggers@group1-v1-price-v1` becomes a direct T15 upstream dataset. Its 4,752 legacy
   receipts have the same known missing distribution fields and require a separate append-only,
   read-only receiver supplement. No T10 byte or receipt may be modified.
5. The failed Run and its partial work remain preserved. Its Authority and bins are invalid after
   the code correction. A successor Authority, TRAIN bin set and one successor Run may be created
   only after this CR is approved, the 4,752-partition supplement and fresh audit PASS, and the
   repository quality gate PASS.
