## Trigger

S2-T15 v1.2 authorizes only the conditional-matching method fixture. Its section 14/21 requires a
new Task version before adding a formal full-research CLI. The current progress service and HTML
stop at S2-T14 and cannot automatically display T15 evidence. Continuing without approval would
invent a publication/input contract and expand into files outside the Task boundary.

## Requested minimum scope

Promote S2-T15 to v1.3 and authorize only:

- a read-only full-input contract binding the accepted T10/T13/T14 and T19 evidence needed to
  construct event/control rows without modifying upstream artifacts;
- frozen training-fold quintile snapshots, period/split/purge/embargo bindings and a compact
  append-only Authority/Run/Manifest/Catalog/Verify chain;
- the minimum full-run CLI and matching tests under the S2-T15 implementation paths;
- a lightweight repository summary plus T15 Task/validation/traceability records;
- the existing progress server, HTML and progress tests solely for read-only T15 projection.

No placebo, clustering, bootstrap, Stage 2 Go/No-Go, H3, Stage 3 or live execution is added.

## Contract to freeze before execution

1. Bind exact immutable upstream Run, Snapshot, Manifest, Catalog, file hashes, code commits and
   row counts before a T15 Run ID exists.
2. Freeze the eligible event universe, non-event control universe and the join that supplies trend,
   volatility, Trades activity, UTC bucket/quarter, period, split/fold and setup/context identity.
3. Quintile boundaries come only from the corresponding training fold; invalid five-bin formation
   blocks the Run and cannot be replaced after observing results.
4. Enforce exact non-relaxable fields and cumulative L0-L4; L5 remains UNMATCHED. Select exactly
   five unique controls with seed `20260716` and report reuse.
5. Publish compact matches/summaries and audit bindings; do not copy or rewrite upstream T13/T14
   row evidence. Verify must rescan and deterministically reproduce all aggregates.
6. BTC and ETH, setup, context, period and split/fold remain separate. Primary treats AMBIGUOUS as
   failure and uses Episode-equal weighting.
7. The UI derives status from newest valid combined evidence; raw HTML never presets PASSED and
   offers no mutation controls. Stage 3 remains locked.

## Acceptance tests

- missing/tampered/symlinked/drifted upstream evidence fails before a Run ID exists;
- exact fields, L0-L5, time boundaries, purge/embargo, five unique controls and fixed-seed
  determinism pass;
- training-only bins and manifest hashes fail closed on drift;
- all eligible Episodes are MATCHED or UNMATCHED exactly once and compact totals reconcile;
- missing, active, failed, malformed, tampered or newer-invalid evidence never renders PASS;
- directed tests, strict traceability, full quality gate and live browser inspection pass.

## Post-approval pre-Run audit

The mandatory read-only input audit completed before an Authority or Run ID was created and found
that the repository and its complete Git history contain references to previously approved
volatility and Trades-activity formulas, but not the formulas themselves. The same audit found no
exact research split/fold boundaries, no exact purge/embargo duration, and no deterministic
non-event control-anchor construction rule. The preregistration records only the period-safe lower
bound `purge >= max lookback + max episode/horizon`, which is not an executable value.

These definitions determine bin membership, control eligibility and sample counts. Inferring them
inside the runner would change a preregistered matching contract after approval and could make the
result data-dependent. Under ADR-S2-004 invalidation semantics and the repository fail-closed
rules, CR-2026-025 is therefore `APPROVED / BLOCKED BEFORE AUTHORITY OR RUN` pending OQ-S2-005.
No Authority, Run ID, output, publication, Verify evidence or UI PASS projection was created.
