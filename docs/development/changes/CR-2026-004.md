## Discovery

After the CR-2026-003 archive-path correction passed its regression and unified quality gates,
the mandatory pre-publication audit inspected retained BTCUSDT `V1_PRICE` evidence from failed
run `stage2-g1-full-a-20260716-4c15e46`. The first 50 daily MarketEpisode partitions contain
3,781 rows but only 971 distinct `(market_episode_id, candidate_version_id)` pairs: 2,810 rows
are exact candidate-identity duplicates.

The first affected day, 2020-01-01, contains three MarketEpisode rows but only two distinct
candidate identities. One identity is emitted for both `G1-HOLD_3-V1` and `G1-TIMING_T1-V1`;
both corresponding `candidate_inclusion` rows are incorrectly marked `included=true` with
`CANDIDATE_INCLUDED`.

## Root cause

S2-T09 delivered and tested `CandidateInclusionLedger`, stable MarketEpisode identity and a
separate candidate-version identity. The S2-T10 `price_phase` integration does not consume that
ledger. It directly appends every episode and emits an inclusion record with `included=true`.
In addition, `build_market_episode` receives the key-level lineage parameter set
`KEYLEVEL-BASE-V1`; the actual OFAT `event_parameter_set_id` is only appended to the serialized
row after candidate identity construction. Consequently distinct research parameter sets can
share the same candidate identity and all be recorded as included.

This is not caused by Stage 1 Trades path discovery and is not authorized by CR-2026-003.

## Affected rules and acceptance gates

- `EVENT-CONSUME-MARKET-EPISODE`
- `GATE-STAGE-2`
- S2-T09 stable identity and research-inclusion deduplication contract
- S2-T10 acceptance: no duplicate episode/candidate, deterministic deduplication and one
  candidate inclusion per identity

Starting either recovery full run with the current pipeline would deterministically create an
invalid candidate dataset. A quality report could not truthfully be PASS.

## Proposed behavior

1. Preserve the FROZEN four-field `market_episode_id` exactly.
2. Bind `candidate_version_id` to the actual approved event parameter set, without adding that
   parameter to `market_episode_id`.
3. Apply the existing S2-T09 research inclusion ledger (or an equivalent deterministic
   partition-safe implementation) across the complete instrument/variant candidate set.
4. Emit one included record per unique `(market_episode_id, candidate_version_id)` and explicit
   `DUPLICATE_CANDIDATE` records for rejected duplicates.
5. Apply the approved gap/re-arm consumption rules at the full-pipeline boundary and report raw,
   included and rejected counts.
6. Add a regression reproducing the 2020-01-01 cross-parameter duplicate and prove deterministic
   results across worker order and daily partition boundaries.
7. Re-run the PRICE fixture and full Group-1 quality gates before freezing a new Execution
   Manifest.

## Deterministic diagnosis

Muce approved a two-step diagnosis and implementation process. The read-only diagnosis over the
first 50 retained BTC PRICE partitions classified all 3,781 records:

- 633 legacy candidate identities are singletons;
- 338 legacy identity-conflict groups contain 3,148 rows;
- Case A exact duplicate excess: 0;
- Case B same semantic event with different legacy identities: 0;
- Case C legacy identity with different semantic payload: 3,148 rows;
- the previously suspected 2,810 duplicates are the excess rows inside those Case C groups;
- ownership by `available_at_ts` UTC date is correct for all 3,781 records.

The approved canonical identity includes the actual OFAT parameter set and timing combination.
Under that definition all 3,781 records have unique identities, with zero identity conflict and
zero exact duplicate. Therefore 971 is only an invalid legacy-identity count and must not be used
as the canonical candidate count.

## Decision

Muce approved CR-2026-004 at L2 and explicitly chose to split legacy Case C groups into distinct
semantic candidates using the new canonical identity. The FROZEN four-field MarketEpisode
identity remains unchanged. S2-T09 and S2-T10 are reopened for this bounded correction. No full
S2-T10 run or new Execution Manifest is authorized until the correction, two deterministic
50-day replays and all quality gates pass.

## Resolution

Muce resolved this L2 change after implementation and validation PASS. The legacy identity
omitted the registered variant and actual OFAT parameter/timing facts, causing distinct research
variants to collide. The canonical candidate identity now separates all 3,781 legitimate
candidates with zero duplicate or identity-conflict groups; no legacy excess row is deleted.
Primary and exploratory parameter variants must remain explicitly classified and separately
counted in every S2-T10 publication. This resolution changes neither V1.3.4, Stage 1 nor the
preregistered research parameter family.
