## Requested repository-wide execution rule

Before every long-running or full-data task, execute a bounded rehearsal over seven complete
consecutive UTC days unless an approved task contract requires a stricter representative window.
The rehearsal must use real read-only inputs where available and exercise producer computation,
serialization, strict consumer read-back, checkpoint or receipt shape, reconciliation,
verification and any in-scope read-only UI projection. It must use isolated unpublished output and
must not create formal Authority, Binning Set, Run ID or research results.

A unit test, schema-only fixture or producer-only write does not satisfy this gate. Any Decimal,
JSON, Parquet, timestamp, path, Hash, checkpoint, receiver, grouping, reconciliation or UI
projection problem blocks the long task. After a correction, the complete rehearsal must restart
from the beginning. A passing seven-day rehearsal reduces execution risk but does not replace the
mandatory full-data validation.

The general rule is recorded in the repository root `AGENTS.md` at Muce's explicit instruction.
