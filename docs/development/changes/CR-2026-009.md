## Historical blocking discovery

At approval time, the fixed Run A was 9,508/9,508 complete, with zero failed and zero UNKNOWN
tasks, but was not published. A release-only restart was stopped during read-only directory
enumeration after audit
found that the current CR-2026-006 release tool does not meet the required atomic recovery
contract:

1. it renames `staging/data` to `published/data` before persisting `DATA_RENAMED`, leaving an
   unrecoverable crash window;
2. cached release shards are not bound by their own physical hashes and supplement authority;
3. release recovery has no single-writer lock;
4. rename, state, checkpoint and publication-journal durability lacks the required fault-injection
   evidence.

The Runtime V2 implementation also exposes an operational `release` command although
CR-2026-007 and S2-T10 v1.8 currently enumerate only six commands. `compare` writes append-only
comparison evidence while its current governance text calls it read-only, and there is no approved
operator command for freezing source authorities, Run A protection, migration and Runtime
Manifests.

The first Runtime V2 authority-freeze attempt,

Bundle. Stage 1 legitimately contains both Catalog-authorized monthly `archive=YYYY-MM` partitions

monthly form and rejected `archive_partition=2026-07-01`. This is an authority-freeze contract

The failed Authority run remains immutable and cannot be promoted to success. CR-2026-009 remains
`APPROVED`; implementation is `IMPLEMENTED` and validation is `PASS_READY_FOR_RESOLUTION` because

has been created or executed. Exact Bundle and component hashes are stored in its append-only

## Proposed bounded decision

If approved, this CR authorizes only the following implementation corrections:

1. create a new append-only Run A release supplement and shard-adoption Manifest; the existing
   Execution Manifest, CR-2026-006 supplement, staging and sealed-shard evidence remain unchanged;
2. bind every adopted shard by path, physical SHA-256, source fingerprint, source checkpoint,
   prior supplement and release-tool commit;
3. add a durable single-writer lock, pre-rename intent journal, directory fsync and deterministic
   recovery for `staging missing + published present` after a successful rename;
4. add fault-injection tests for shard tampering, concurrent recovery and every publication state;
5. add `release` to the approved Runtime V2 command surface so generation, publication and verify
   remain separate bounded-memory processes;
6. classify `compare` as a mutating append-only evidence command with write probe and run lock;
7. add a fixed authority-freeze operator command for Contract Price inventory, Trades resolved
   index, Run A protection, migration Manifest and Runtime Manifest;
8. approve the three `DIAGNOSTIC_ONLY` bounded-memory scripts as validation tools only;
9. clarify that a sealed Foundation staging authority may feed Group 1 inside the same Run B, with
   the combined snapshot published only after every Foundation and Group-1 gate passes.
