## Blocking discovery

The first conditionally authorized V2 Run B preflight stopped before consuming its reserved run ID.
The frozen V2 branch parsed exactly one protected Run A Execution Manifest but zero protected
release supplements. Formal Run A binds release supplement v1.1 under CR-2026-009 with complete
shard-adoption authority, while the V2 copy of `Stage2ReleaseSupplementManifest` accepted only
v1.0 under CR-2026-006. The generic `ambiguous` error therefore represented a missing compatible
supplement parser, not duplicate Run A evidence.

The blocked preflight created no Run B directory and executed no Foundation, Group-1, comparison
or later-group work. Its authorization and blocked receipts remain append-only in the superseded
Authority run.

1. accept release supplement versions 1.0 and 1.1 and CR-2026-006/CR-2026-009 without changing
   the v1.0 canonical hash;
2. require all four shard-adoption bindings for v1.1/CR-2026-009 and forbid them for v1.0;
3. distinguish missing or duplicate Execution Manifest and release supplement match counts;
4. prove the formal Run A v1.1 supplement and protection resolve exactly once;
5. invalidate the superseded Authority and reserved, never-created Run B ID with append-only

6. bind a new Authority Bundle and unique successor Run B to the final correction commit;
