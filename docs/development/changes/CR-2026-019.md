## Trigger and root cause

CR-2026-018 published and independently verified the fixed 80,784-partition Run, then failed
closed before exact comparison. The production backend filters individual V2 Receipts using the
required uppercase receipt marker `ERA_CANONICAL_JSON_ROW_V1`, but passes that marker as
`v2_legacy_hash_algorithm` to `compare_run_a_to_v2_sorted_stream()`. That argument is a distinct
algorithm-authority field and must equal lowercase `era-canonical-json-row-v1`.

The comparator rejected the wrong argument before consuming its first Receipt. Therefore the
failure was not a 61,776-partition mismatch and supplied no evidence for or against Run-A
equality.

## Approved correction

1. Change only the production comparator call to pass `LEGACY_HASH_ALGORITHM` as
   `v2_legacy_hash_algorithm` while retaining the uppercase per-Receipt filter.
2. Add a production-boundary regression that captures the comparator keyword argument and fails
   on the prior uppercase value; retain all existing Receipt marker tests.
3. Run the complete quality gate and strict Traceability.
4. Freeze an append-only comparison-only amendment bound to the existing published Catalog,
   CR-2026-018 Authority, Run-A protection and unchanged sealed input set.
5. Execute only Compare; do not republish, regenerate Verify, resume, adopt, repack, mutate,
   delete or create a successor.
6. Accept only `matched_partition_count=61,776`, `difference_count=0`, zero missing and zero extra.
