# CR-2026-051 — 零-Trade 秒使用已绑定 Contract Price 价格代理

- status: `APPROVED`
- approved_by: `Muce`
- approved_at: `2026-07-30`
- applies_to: `stage_2_plan_v1.10 / S2P110-T11`

## 背景

正式 Run `stage2-s2p110-20260729T162336Z-e2d0272d8420` 在 T11 发现 Trade 缺口与
零成交量 Contract Price 秒重叠，并按 ADR-S2-026 的旧规则失败关闭。该 Run 保持
`FAILED_UNPUBLISHED`，不得 resume 或改写。

## 批准决定

当 canonical Trades 在受影响秒不可用时，`CONTRACT_PRICE_OHLC_PRIMARY` 直接使用已由
独立 Hash、receipt 和时间范围绑定的 Contract Price 1s OHLC。`volume=0` 只表示该秒
没有新 aggTrade；OHLC 必须为平坦状态，随后仍按同一 target/stop 边界合同分类。

这不创建 Trade、Trade ID、成交、滑点或秒内顺序；`synthetic_execution=false` 和
`intrasecond_order_known=false` 保持不变。非平坦零成交量 OHLC、Contract Price 缺失、
重复秒、Hash 漂移或来源范围不闭合仍失败关闭。

CR 只替代 ADR-S2-026 中“零成交量秒不能恢复 Trade 缺口”这一条；其余双轨、AMBIGUOUS、
BTC/ETH 隔离、H2 Primary 和 Stage 3 锁保持不变。

## 证据

固定日期 `2020-01-01`、BTC/ETH 分别等距抽取100个有 Trades 的秒及最多20个零-Trade
秒。200/200 个有 Trades 秒的 Contract Price low/high 与 Trade min/max 精确一致；
40/40 个零-Trade秒为平坦 OHLC 且没有可见 canonical Trade。
