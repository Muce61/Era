## Trigger

S2-T12 requires the existing read-only progress page to recognize the Task automatically from real
run and validation evidence. If that is impossible inside the approved S2-T12 file scope, work must
stop at the observability boundary and submit a minimal scope amendment rather than hard-code PASS.

The live audit found that the current server and page are still fixed to S2-T11:

- `scripts/run_stage2_progress_server.py` projects only `stage2_tasks["S2-T11"]`;
- `scripts/stage2_progress_ui.html` renders and evaluates only the S2-T11 task node and flow;
- neither surface recognizes an S2-T12 Authority, execution Manifest, Catalog, quality report or
  repository validation;
- raw HTML defaults to S2-T11 CHECKING, so it cannot truthfully show S2-T12 while the full run is in
  progress or after verification.

No UI file was modified during S2-T12 implementation. The in-scope historical path-metric run may
finish and preserve its append-only evidence, but S2-T12 must not be presented as automatically
observable until this amendment is approved and validated.

## Requested minimal scope

Authorize only these additional observability files on the existing S2-T12 branch:

- `scripts/run_stage2_progress_server.py`;
- `scripts/stage2_progress_ui.html`;
- `tests/scripts/test_stage2_progress_server.py`;
- `tests/research/stage_2/runtime_v2/test_progress.py`.

The existing S2-T12 implementation and evidence allowlist remains unchanged. No other runtime,
source-data, Stage 1, Stage 3 or later-Task file is added to scope.

## Required design

1. Extend the existing read-only task projection to S2-T12 without embedding a PASSED constant.
2. Derive state only from the newest valid S2-T12 append-only Authority/run evidence, read-only
   verification and repository validation. Missing, partial, malformed, failed, conflicting,
   symlinked or unpublished evidence must never produce PASS.
3. Display BTC and ETH separately and H1 and H2 separately, with episode/metric-row counts,
   registered check counts and the current immutable Run ID.
4. Label MFE, MAE, Time-to-Activation and Time-since-MFE as historical price-path evidence only;
   never label them PnL, return, real execution or live protection.
5. Preserve S2-T10 and S2-T11 accepted projections unchanged and keep Stage 3 LOCKED regardless of
   S2-T12 state.
6. Keep the page read-only. It may not start, resume, verify, publish, mutate, delete or clean any
   research execution.

## Acceptance tests

- no S2-T12 evidence renders NOT_STARTED or CHECKING, never PASS;
- an active unpublished run renders IN_PROGRESS without promoting partial output;
- a terminal failed unpublished run renders FAILED with its auditable reason;
- PASS requires the same fixed Authority, complete BTC/ETH H1/H2 Catalog, quality PASS, read-only
  Verify PASS, all registered checks and repository validation PASS;
- the displayed counts and Run ID equal the immutable evidence files;
- raw HTML contains no hard-coded S2-T12 PASSED state;
- S2-T10 and S2-T11 regressions continue to pass and Stage 3 remains LOCKED;
- directed UI/server tests, full quality gate and live browser inspection pass with no console
  errors.

## Explicit non-goals

This amendment does not change metric formulas or thresholds, repair source data, modify frozen
Stage 1 files, run first-passage or AMBIGUOUS bounds, implement S2-T13 through S2-T20, approve
S2-T12, or unlock Stage 3. It only requests the minimum additional files needed to make S2-T12
truthfully observable.

## Decision and implementation result

Muce approved this bounded amendment on 2026-07-21. The four authorized UI/server files now:

- select the newest S2-T12 Run without falling back past newer terminal evidence;
- fail closed for missing, partial, malformed, conflicting, symlinked, failed or unbound evidence;
- require the fixed Authority, execution Manifest, immutable Snapshot, self-hashed Manifest and
  Catalog, separate BTC/ETH H1/H2 completion, repository summary, Verify PASS, validation PASS,
  historical-only labeling and the Stage-3 lock before displaying PASS;
- display the immutable Run ID, BTC/ETH row counts and registered check count while remaining
  read-only.

Validation passed with 21 directed UI/server tests, the full 480-test quality gate and a live
browser inspection. The formal S2-T12 computation was not rerun and no sealed or published artifact
was modified. This CR closes only the UI observability gap; S2-T12 still awaits separate human
acceptance, S2-T13 remains unapproved and Stage 3 remains locked.
