## Trigger

Run `stage2-g1-v2-b-20260719T141315Z-bf8c6a186f66` completed and sealed all 80,784 V2 logical
partitions, including all 61,776 Group-1 partitions, but failed unpublished while constructing the
first production component. The packer ordered artifacts by `(dataset_spec_hash, object_sha256)`;
the consuming `Group1TaskComponent` contract requires the tuple to be unique and sorted only by
`object_sha256`.

The append-only audit `reports/cr-2026-015-packed-artifact-audit.json` proves that the failed
component had 19 packed seals and 19 distinct physical artifact Hashes. No duplicate artifact was
found. The terminal failure is therefore a sort-order contract mismatch, not duplicate content.

## Approved correction

1. Sort component artifact evidence by `object_sha256`, and fail closed if that physical Hash is
   repeated; do not silently deduplicate.
2. Keep the failed run `FAILED_INTEGRITY` and unpublished. Its checkpoint, Manifest, monthly
   evidence, partials, logs and the 19 failed packed objects remain immutable.
3. Create a new Authority and new Run B. Adopt only fully validated Foundation and Group-1 monthly
   objects, receipts, seals and checkpoints from the failed run.
4. Do not adopt Group-1 packed objects, packed seals, partials or processing-day caches. The new run
   must execute final packing, release, verify and Run A/Run B comparison under corrected code.
5. Show failed-run protection, duplicate audit, monthly adoption, packing, release, verify and
   comparison as separate read-only Web subflows, including progress, elapsed time and recent logs.

## Acceptance

The duplicate audit must report zero duplicate physical artifacts. Every adopted object must pass
physical SHA, Parquet row-count, receipt, seal, checkpoint and semantic-authority checks. The new
run must recreate final packed objects, publish atomically, verify all 80,784 V2 partitions and
match Run A across all 61,776 Group-1 partitions. Any integrity or semantic mismatch stops S2-T10.
