## Evidence-backed problem

Muce stopped the active TRAIN-bin preparation after the read-only progress view exposed a data
availability question. No Binning Set or Run ID was created. Six complete prepared BTC blocks and
one incomplete temporary block remain preserved, unpublished and non-reusable under a different
Authority.

The completed `BTCUSDT/P1/B0` block contains 210,240 grid anchors. Exactly 210,179 have an
available 61-bar price feature and 61 are classified `PRICE_FEATURE_UNAVAILABLE`. Those 61 anchors
occur every minute from `2020-01-01T00:00:09Z` through `2020-01-01T01:00:09Z`. The accepted T10
Foundation has no `2019-12-31` causal-price partition, while the first `2020-01-01` bar becomes
available at `00:01:00Z`. The other five complete prepared blocks have zero unavailable
price/activity/context rows. An equivalent whole-range BTC/ETH audit has not yet been completed,
so the 61-row observation must not be generalized to ETH or to all periods.

## Proposed missingness taxonomy

Every unavailable row must enter exactly one mutually exclusive class:

1. `BOUNDARY_WARMUP_UNAVAILABLE`: the frozen lookback extends before the accepted dataset start.
2. `DECLARED_SOURCE_GAP`: the accepted source explicitly records an incomplete interval.
3. `UNBOUND_SOURCE_PARTITION`: an expected partition, receipt or Hash cannot be bound.
4. `FEATURE_VALUE_INVALID`: all source rows exist but the frozen feature contract rejects a value.
5. `AVAILABLE_ZERO_ACTIVITY`: complete source coverage with zero Trades; this is available data,
   not missing data.
6. `AVAILABLE_ZERO_OBSERVATIONS`: a complete H2 outcome window with no Trades; it retains T13's
   `AMBIGUOUS / NO_OBSERVATIONS / strict=0` semantics and is not `EXPIRED`.

## Proposed decision

- Never forward-fill, backward-fill, interpolate, shorten the 61-bar window or interpret missing
  source as zero.
- A proven dataset-boundary warmup anchor may be excluded with its explicit reason and full
  instrument/period/fold reconciliation. The period boundary and grid must not be silently moved.
- `UNBOUND_SOURCE_PARTITION`, receipt drift or Hash drift is a run-level hard failure.
- A declared H2 gap remains AMBIGUOUS under the accepted T13/T14 policy; an undeclared or unbound
  gap blocks the Run.
- Before any new Authority, run a read-only BTC/ETH whole-range availability audit covering every
  feature source and every planned lifecycle horizon. Publish counts by instrument, period, fold,
  date and reason.
- If an earlier historical partition is needed to eliminate boundary warmup, it requires a
  separately approved Stage 1 supplementation/baseline change. T15 may not manufacture it.
