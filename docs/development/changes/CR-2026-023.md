## Trigger

S2-T13 v1.2 now has a tested deterministic fixture implementation, but its own section 14/21 says
the formal full-run CLI must be frozen in a new Task version after S2-T19 preregistration. It does
not authorize a repository CLI, external output layout, append-only Authority/Manifest/Catalog or
publication protocol. Separately, the current read-only progress service and HTML project only
S2-T11 and S2-T12, so they cannot automatically display S2-T13 evidence.

Continuing without an amendment would either invent an unapproved full-run contract or hard-code a
UI result. Both are forbidden.

## Requested minimum scope

Promote S2-T13 to v1.3 and authorize only:

- `src/era100x/research/stage_2/labels/first_passage/full_run.py`;
- `scripts/run_stage2_first_passage.py`;
- matching tests under `tests/research/stage_2/labels/first_passage/` and
  `tests/scripts/test_stage2_first_passage.py`;
- the existing S2-T13 Task, validation, CURRENT_STAGE, TRACEABILITY, direct `rules.yaml` mappings
  and a lightweight repository audit summary;
- `scripts/run_stage2_progress_server.py`, `scripts/stage2_progress_ui.html` and their two existing
  progress test files, solely for read-only S2-T13 automatic projection.

No other source, Stage 1, accepted S2-T11/S2-T12 evidence, T14+ implementation or Stage 3 path is
added to scope.

## Contract to freeze before execution

1. Bind the accepted S2-T11 Snapshot, frozen S2-T19 target/stop/horizon domains, source hashes,
   code commit, output root and historical-only semantics into an Authority before a Run ID exists.
2. Keep BTC/ETH and H1/H2 separate. Preserve MarketEpisode lineage and V2 H2 stable ordering.
3. Produce all registered target × stop × horizon classifications without selecting a favorable
   subset after observing results. Use a preflighted deterministic layout and resource estimate.
4. Preserve raw `AMBIGUOUS` plus adverse-first main handling for H1 same-event double touches, but
   do not calculate T14 optimistic/pessimistic bounds.
5. Publish atomically with self-hashed Manifest/Catalog and failure evidence; failed runs remain
   unpublished and immutable. Verify hashes, counts, domains, lineage, isolation and deterministic
   recomputation read-only.
6. The UI derives NOT_STARTED/IN_PROGRESS/FAILED/PASS only from the newest valid append-only Run,
   repository validation and Verify evidence. Raw HTML must not preset S2-T13 PASSED.
7. Stage 3 remains locked in every state. No page control may run, resume, publish, delete or mutate
   research evidence.

## Acceptance tests

- preflight creates no Run ID and fails closed on changed inputs, symlinks or unregistered domains;
- normal, boundary, gap, truncation, same-event, shuffle and deterministic-replay tests pass;
- formal BTC/ETH H1/H2 counts and all registered target/stop/horizon combinations are complete;
- no PnL, return, ROUND_SUCCESS, live-execution or T14-bound field is emitted;
- read-only Verify and repository validation pass;
- missing, partial, failed, malformed, conflicting or newer invalid UI evidence never renders PASS;
- directed tests, strict traceability, full quality gate and live browser inspection pass.

## Explicit non-goals

bootstrap, S2-T20 or Stage 3. It does not rerun or mutate S2-T11/S2-T12, and it does not connect any
real API, testnet or funds.
