## Blocking evidence

Replacement Run B `stage2-g1-v2-b-20260718T141137Z-f0c150bfa1c9` completed all 316
BTCUSDT month-level Foundation objects, then failed before packing and Task receipt sealing. Its
phase baseline current RSS was `245,186,560` bytes, current RSS was `1,639,940,096` bytes and
lifetime peak was `1,697,202,176` bytes. The implementation classified the
`1,394,753,536` byte phase-current increase as a terminal `MemoryError` even though current RSS
remained below 3 GiB and no data-integrity, research-semantic or authority violation existed.

The run is permanently `FAILED_UNPUBLISHED`, has zero published files and may not be resumed,
rewritten, published or cleaned. Its immutable month objects may only be consumed by a new run
through the separately sealed adoption contract defined below.

## Approved correction

1. Memory, Arrow inflight, object-count, object-size, capacity-estimate and performance thresholds
   are observation thresholds. Exceeding one records a deterministic resource anomaly; it does
   not itself fail research or publication quality.
2. Runtime mitigation is deterministic: release source references, collect garbage, reduce the
   bounded batch/window and split at UTC-day ownership boundaries where supported.
3. If execution cannot continue safely, it checkpoints `PAUSED_RESOURCE_PRESSURE` or
   `PAUSED_STORAGE_UNAVAILABLE`; it does not write terminal integrity failure evidence.
4. `FAILED_INTEGRITY` is reserved for authority/hash/schema/checksum/identity/ownership/leakage,
   append-only or exact-comparison violations and actual data corruption.
5. Resource anomalies are append-only execution evidence. They are excluded from candidate,
   payload, logical-partition and dataset semantic hashes.
6. Publication may be `PUBLISHED_WITH_RESOURCE_ANOMALIES` when all semantic quality gates pass.
7. A new replacement Run B may adopt the 316 sealed BTC month objects only after verifying every
   physical hash, Seal, Receipt, Schema, source authority, code-generator tree, config, snapshot
   and owner-day range. The old run remains immutable; a new `ArtifactAdoptionManifest` records
   every adopted or rejected object.
8. A rejected object is rebuilt individually. Authority, generator-tree or semantic incompatibility
   invalidates the whole adoption attempt and requires a complete BTC Foundation rebuild.
9. The replacement must still build 80,784 V2 logical partitions and exactly compare all 61,776
   Group-1 partitions with formal Run A before S2-T10 or Group 1 can pass.

This change does not alter Stage 1, Run A, Preregistration, config hash, research parameters,
event definitions, candidate identity, MarketEpisode identity, payload hash or comparison rules.
S2-T11 through S2-T20 remain DRAFT and unexecuted.

## Implementation checkpoint

The implementation gate records resource crossings through `ResourceAnomalyV1`, preserves them
in append-only physical evidence and excludes them from semantic hashes. Runtime checkpoints now
distinguish anomaly-running, recoverable resource/storage pauses and integrity failures. The
Foundation and Group-1 packers no longer turn RSS, Arrow, shard-size or object-count observations
into research failures. Exact authority, checksum, Schema, receipt, identity, ownership and
comparison gates remain fail-closed.

The Runtime V2 directed suite passed 191/191 and the repository quality gate passed 397/397 with
Ruff, strict mypy and strict Traceability. Validation remains PENDING until the final-code
Authority, 316-object adoption, replacement Run B, publication and exact Run-A comparison finish.

The first post-correction replacement run completed both Foundation tasks, then failed unpublished
because the Group-1 loader attempted to parse the newly bound resource-anomaly evidence as a
Foundation shard checkpoint. This was a supporting-evidence routing defect, not a semantic or
data-integrity difference. The loader now validates resource evidence separately, accepts shard
checkpoints only from the approved packed-checkpoint prefix and rejects every unknown evidence
class. The regression and unified 399-test gate pass; the failed run remains immutable.
