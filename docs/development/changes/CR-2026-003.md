## Discovery

The first BTCUSDT `V1_FLOW` partition in full run
`stage2-g1-full-a-20260716-4c15e46` failed before reading data. S2-T10 resolved the
frozen Stage 1 Trades partition as:

`BTCUSDT/date=2020-01-01/part-000.parquet`

The immutable Stage 1 published Catalog uses the physical layout:

`BTCUSDT/archive=2020-01/date=2020-01-01/part-000.parquet`

The published file exists at the latter path. No Stage 1 data, Manifest, Catalog or logical
hash changed.

- source: actual S2-T10 full-run failure
- run_id: `stage2-g1-full-a-20260716-4c15e46`

## Affected rules and current behavior

- affected rules: `DATA-HISTORICAL-NO-FAKE-EXECUTION`, `GATE-STAGE-2`
- current behavior: the S2-T10 Flow reader hard-codes a non-canonical physical path and fails
  before consuming the first valid Stage 1 Trades partition.
- safety behavior: the run remains unpublished, failed staging is retained, and no fallback
  input root is permitted.

## Proposed behavior

1. Resolve Stage 1 Trades through its published Catalog/Manifest or the exact approved
   `instrument/archive=YYYY-MM/date=YYYY-MM-DD/part-000.parquet` layout.
2. Add preflight validation for all BTCUSDT and ETHUSDT daily Trades partitions before starting
   full generation.
3. Add regression tests for the archive/date layout and for failure before publication.
4. Reopen S2-T10 under a new Task version and generate a new execution Manifest/code binding.
5. Start a new append-only full run; do not resume or publish the failed run.
