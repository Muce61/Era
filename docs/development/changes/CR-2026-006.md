## Decision

Muce approved a bounded L2 separation between the immutable event-generator provenance and the
release-tool provenance. The specified v1.6 Run A completed all 9,508 planned generation and
finalization items with zero recorded failures, but publication was stopped by the user before
Catalog, quality reports or `published/data` were created. Its event staging may be released only
through an append-only `Stage2ReleaseSupplementManifest` that binds the original Execution
Manifest, generator tree, release-tool tree, Stage 1 and preregistration hashes, source checkpoint,
all four finalization reports and quality evidence.

The original Execution Manifest remains immutable. This change does not authorize any event,
identity, payload, parameter or Stage 1 change. The optimized publisher performs one deterministic
deep scan, creates recoverable sealed dataset shards, then uses same-volume atomic rename and a
structural post-rename check. Deep-scan or quality failure terminates as `FAILED_UNPUBLISHED` and
does not fall back to rebuilding Run A.

Run B may be created only after Run A publishes with Quality PASS. Run B must be a fresh full build
from the frozen Stage 1 baseline, must bind the same generator semantic tree and use the same
release tool, and may not reuse Run A artifacts. S2-T10 and Group 1 remain incomplete until both
runs and their deterministic comparison pass. S2-T11 through S2-T20 remain unapproved and
unexecuted.
