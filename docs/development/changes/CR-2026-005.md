## Discovery

The first approved v1.5 full build, run
`stage2-g1-full-a-20260716T122601Z-0247d30f9f62`, completed all 2,376 BTCUSDT
`V1_PRICE` daily construction partitions. Deterministic candidate finalization then stopped on
owner date `2020-04-27` because two canonical candidate identities each had two distinct
`canonical_payload_hash` values. The run was not published and Run B was not created.

The conflict report is retained at:

`reports/candidate_identity_conflicts/instrument=BTCUSDT/variant=V1_PRICE/date=2020-04-27.json`

under the failed run. It records:

- candidate `377ea4...ca617`: payloads `a0a2ab...32860` and `bd62dd...57b02`;
- candidate `a55902...9d07`: payloads `33cc9e...32f4` and `cea881...7f9d07`;
- two attempts per identity, all owned by `2020-04-27`;
- no publication and no Stage 1 mutation.

## Deterministic root-cause observation

For each conflict group, the serialized candidate contract fields are equal except for
`canonical_payload_hash` and the source row ordinal. The event parameter set, timing, key-level,
Sweep, Reclaim, Hold, Trigger, availability, Stage 1 baseline and config identity fields match.

The upstream fact comparison shows that the same canonical key level and same event chain were
constructed from two adjacent minute iterations. The `CanonicalKeyLevel` snapshots have the same
`key_level_id` but `expires_at_ns` differs by exactly 60 seconds. `expires_at_ns` participates in
the approved semantic fact payload hash, while the canonical candidate identity intentionally
binds the stable `key_level_id`, not the mutable processing snapshot. The finalizer therefore
correctly hard-fails rather than silently choosing one payload.

The current PRICE day builder scans up to 121 seconds from each minute seed. Adjacent minute
seeds can consequently observe the same later Sweep and build the same event chain from two
successive validity snapshots. The first 50-day CR-2026-004 diagnostic did not contain this
later occurrence and therefore did not expose the integration defect.

## Decision options

### Option A — Event-seed ownership by Sweep start minute (recommended)

Accept an event chain only in the unique minute seed containing `sweep_start_ts`, using a UTC
left-closed/right-open minute. Later facts may still be read causally through their approved
detection boundaries. Adjacent seed windows may provide context but cannot emit the same Sweep.

Impact: preserves the approved candidate identity and complete semantic payload hash, removes
processing-window duplication at its source, and should leave one semantic candidate for the
observed event. It changes S2-T10 output rows/logical hashes and requires a red regression,
full Group-1 regression, a new execution Manifest and two entirely new full runs.

### Option B — Exclude mutable key-level expiry from candidate semantic payload

Treat `CanonicalKeyLevel.expires_at_ns` as snapshot execution metadata for candidate hashing.

Impact: the finalizer would classify these attempts as exact duplicates, but this weakens the
previously approved rule that semantic fact payload hashes cover the CanonicalKeyLevel fact. It
risks hiding other snapshot differences and requires explicit approval of the semantic payload
projection.

### Option C — Add the key-level validity snapshot to canonical candidate identity

Bind `expires_at_ns` or an explicit snapshot version in candidate identity.

Impact: both attempts become distinct candidates even though they represent the same Sweep and
event chain. This increases candidate counts from processing-window overlap and is not
recommended without an L3 research-method review.

## Recommendation

Approve Option A as a bounded implementation correction. Keep the FROZEN `market_episode_id`,
CR-2026-004 canonical candidate identity fields, all event definitions, T1-T4, parameter sets,
Stage 1 baseline, preregistration Manifest and config hash unchanged. Add explicit adjacent-minute
and adjacent-day ownership regressions and make runner exceptions persist terminal failure state.

- Other minute/day/month windows remain causal context and emit no Sweep or downstream chain.
- `CanonicalKeyLevel.expires_at_ns` remains in the semantic fact payload.

## Implementation and validation result

Option A is implemented at commit `b72958c0d44fdda8e24d51e56a2f2d603aa957ff`.
The PRICE builder now emits a Sweep and its downstream chain only when the integer UTC
nanosecond `sweep_start_ts` belongs to the current seed minute's left-closed/right-open interval.
Runner failures are recorded as terminal `FAILED_UNPUBLISHED`; identity-conflict evidence is
write-once, while controlled interruption remains recoverable.
