## Problem

The first Policy-v2 formal chain stopped in S2P13-T11 because the sealed Stage 1
`BTCUSDT/2022-03-01` Parquet no longer matched its immutable partition receipt. The file size and
byte Hash drifted and its Parquet footer is truncated. The original Binance official
`BTCUSDT-trades-2022-03.zip` remains locally available, passes ZIP integrity, and matches its
official checksum sidecar.

## Decision

- Never modify, move, delete or overwrite the damaged Stage 1 file or its receipt.
- Rebuild only `BTCUSDT/2022-03-01` from the already accepted official monthly archive.
- Publish the rebuilt partition under a new append-only Stage 2 supplement root.
- Accept it only if its row count, logical Hash, byte Hash, first/last identity, gap, reversal and
  duplicate statistics exactly match the original sealed receipt.
- Bind the supplement acceptance path and Hash through Policy, approval, ChainAuthority and T11
  output. Implicit `latest` lookup is forbidden.
- Preserve the first failed chain. It cannot resume and cannot authorize a successor.
- After implementation, rerun the standard final-code seven-day chain and a separate seven-day
  chain whose scope contains `2022-03-01`. A new commit-bound approval is required before exactly
  one successor formal chain may be created.

## Allowed

- Stage 2 rerun, lifecycle source resolver, lightweight governance and read-only UI code/tests
- one new append-only external Trade supplement and its Manifest/Catalog/Verify/acceptance
- this CR, ADR-S2-020, S2P13-T11 contract and Traceability

## Forbidden

- `docs/spec/**`
- any mutation of Stage 1, T10-T16 historical evidence or the failed formal chain
- missing-as-zero, silent skip, shortened lifecycle window or fabricated Trade rows
- automatic successor creation, S2P13-T17+, Stage 3 or real execution
