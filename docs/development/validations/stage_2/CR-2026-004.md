## Identity, payload and ownership

The V1.3.4 four-field `market_episode_id` remains unchanged. The separate v1 canonical candidate
identity binds variant, instrument, direction, key/sweep/reclaim/hold/trigger facts, timing,
actual parameter set, availability, Stage 1 run/logical hash, config hash and optional Flow fact.
`candidate_version_id` is a checked compatibility alias of `canonical_candidate_id`.

Canonical payload hashing uses versioned UTF-8 JSON, normalized Decimal text, integer UTC
nanoseconds, string Enums, JSON null, sorted Map keys and stable List order. Free metadata and
execution fields are excluded; semantic event-fact payload hashes are included.

The deterministic finalizer owns candidates by `[UTC day start, next day start)`, keeps attempts
outside published data, hard-fails same-ID/different-payload conflicts, selects exact duplicates
by approved source ordering and writes complete exclusion provenance. Flow calculation is
unchanged and can only consume finalized canonical PRICE windows.
