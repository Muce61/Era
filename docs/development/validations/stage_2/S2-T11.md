## Delivered capability

The implementation extracts separate BTC or ETH H1 Contract Price and H2 Trades sequences from
one immutable `MarketEpisode`. Windows use UTC event nanoseconds with left-closed/right-open
semantics. H2 facts use `(instrument, canonical_trade_id)` identity and the exact V2 order
`(ts_event_ns, venue_trade_id, canonical_trade_id)`. Exact canonical duplicates fold;
conflicting venue IDs remain separate facts. H1/H2 source hashes, episode/candidate lineage,
outside-window counts, duplicates, gaps, ambiguity and a deterministic output hash are retained.

The output contract intentionally contains no MFE, MAE, time-to-activation, first-passage,
AMBIGUOUS bounds, return, PnL, matching, placebo, clustering or bootstrap result. Historical
Bid, Ask, receive latency, partial fill and actual slippage fields are explicitly prohibited.

CR-2026-020 adds a generic read-only Stage 2 task receipt projection. S2-T11 PASS is impossible
without a valid append-only receipt chain, complete BTC and ETH inputs/outputs, full-output flag,
validation hash and all registered checks. Missing, malformed, symlinked, conflicting or broken
chains fail closed. S2-T10 exact comparison remains independently projected and Stage 3 remains
locked.
